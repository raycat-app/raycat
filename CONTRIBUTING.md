# Как внести вклад

Спасибо, что хотите помочь raycat!

## С чего начать

- **Ошибка или идея** — откройте [issue](https://github.com/raycat-app/raycat/issues/new/choose)
  по шаблону. Никогда не публикуйте ссылку своей подписки: это ваш пароль.
- **Вопрос** — в [Discussions](https://github.com/raycat-app/raycat/discussions).
- **Уязвимость** — только приватно, см. [SECURITY.md](SECURITY.md).
- **Код** — для заметных изменений сначала обсудите идею в issue. Задачи для
  первого вклада помечены «хороший первый issue».

## Разработка

```sh
cargo build
cargo test
cargo clippy --all-targets
cargo fmt
```

Версия Rust задана в `rust-toolchain.toml`, rustup поставит её сам.

- Комментарии, документация, коммиты, issue и PR — на русском; имена в коде —
  английские.
- Комментарии — только там, где без них не разобраться.
- `unwrap`/`expect` — только в тестах; `unsafe` — только для системных вызовов, с
  комментарием `// SAFETY:`.
- В коде, тестах и логах не бывает настоящих ссылок подписок и ключей.

## PR

1. Форкните репозиторий и создайте ветку.
2. Проверьте локально командами выше.
3. Откройте PR с заголовком в формате
   [Conventional Commits](https://www.conventionalcommits.org/ru/v1.0.0/) и описанием
   со строчной буквы: `feat: автопереключение узлов`, `fix: утечка DNS при перезапуске`.
   Заголовок станет сообщением коммита.
4. Дождитесь зелёного CI и ревью.

## Профили Happ и INCY

Новые версии клиентов вносит бот, руками их менять не нужно. Раз в сутки workflow
«Новые версии клиентов» сравнивает последние стабильные релизы с теми, по которым сняты
образцы запросов (`crates/emulation/captures`, поле `release`). Для новой версии стенд
захвата (`.github/workflows/capture.yml`) снимает запрос настоящего приложения,
инструмент `update-profiles` обновляет профиль и образцы, бот открывает PR
`feat: профиль happ android 4.7.0`, запускает обязательные проверки и сливает его, если
они зелёные.

Если запрос приложения изменился так, что профиль его не выражает (новый заголовок,
другой порядок или маркер), инструмент ничего не меняет, а бот заводит issue с отчётом:
какие заголовки добавились или пропали и какие строки запроса отличаются. Профиль тогда
правят руками, образцы кладут из артефактов прогона:

```sh
cargo run -p raycat-emulation --features tool --bin update-profiles -- \
  happ android --release 4.7.0 --artifacts <каталог с артефактами capture-…> --root crates/emulation
```

Проверить стенд без новой версии можно запуском «Новые версии клиентов» вручную с
параметром `force`: профиль текущей версии пересобирается и не должен измениться.

Отправляя PR, вы соглашаетесь, что ваш вклад распространяется под
[лицензией MIT](LICENSE). Участвуя в проекте, соблюдайте
[правила поведения](CODE_OF_CONDUCT.md).

## Выпуск

Выпуск автоматический: каждое слияние в `main` с зелёным CI публикует dev-сборку, а
выдержавшая срок сборка сама становится stable (подробности в разделе «Версии и каналы»
README). Версия считается по заголовкам коммитов: `feat` — minor, остальное — patch,
`!` в заголовке или `BREAKING CHANGE` в тексте — несовместимое изменение, его в stable
выпускает только владелец вручную. Метка `стоп-релиз` на открытом issue останавливает
продвижение в stable. Исправление уязвимости (метка `безопасность` и заголовок `fix`)
продвигается без выдержки.
